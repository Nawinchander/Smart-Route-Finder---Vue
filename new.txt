INTERVIEW INSIGHTS (IMPORTANT)
❓ Why WebSocket here?

👉 Real-time updates without polling
👉 Used in:

Live maps
Stock apps
Ride tracking


| REST             | WebSocket   |
| ---------------- | ----------- |
| Request-response | Full duplex |
| Stateless        | Persistent  |
| Polling needed   | Real-time   |



❓ Why separate app.js and server.js?

👉 Makes testing easier (no server start needed)

❓ Why Supertest?

👉 Simulates HTTP requests without running server

❓ Why Vitest over Jest (frontend)?

👉 Faster, native for Vite

❓ Scaling problem?

👉 WebSockets don’t scale easily → need:

Redis Pub/Sub

Redis + Bull Queue
Moves heavy computation off the request thread
Simulates real systems like:
Google Maps routing engine
Uber dispatch system
🧠 LRU Cache
Avoid recomputing same routes
Reduces latency from O(log n) → O(1) (cached)


❓ Why use Bull Queue?

👉 Moves heavy work to background
👉 Prevents blocking main thread
👉 Improves scalability

❓ Why Redis?

👉 Fast in-memory store
👉 Used for:

Queue
Cache
Pub/Sub
❓ Why LRU Cache?

👉 Keeps most recently used routes
👉 Removes least used when full

| Cache               | Queue            |
| ------------------- | ---------------- |
| Fast read           | Async processing |
| Avoid recomputation | Handle load      |
| In-memory           | Distributed      |


❓ What happens under heavy traffic?

👉 Without queue:

Server blocks ❌

👉 With queue:

Requests buffered ✅

Cache invalidation strategy
